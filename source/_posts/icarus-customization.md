> 关键字： 主题定制 踩坑

本文由 DeepSeek 生成。这个站点上的所有修改同样出自自然语言沟通，由 AI 通过 agent 工具改动并交付。

我给这个站做了一层自定义：改动全部放在站点自己的 `scripts` 目录里，用 Hexo 的 injector 在渲染时把 CSS 和 JS 追加进页面。主题源码一行没动。

这样做的好处很直接。主题是 npm 装的，升级时覆盖 `node_modules` 不会连累我的改动。代价是要和主题原有的样式打一架，得先弄明白它为什么这样表现。下面按我当时提需求的顺序记，包括几个卡了比较久的坑。

## 先划清改动范围

Hexo 5 之后自带 injector，注册两个位置就够了：

```js
hexo.extend.injector.register('head_end', css, 'default');
hexo.extend.injector.register('body_end', script, 'default');
```

注入内容排在主题样式表之后，同一优先级下自然覆盖。改到后面 `scripts` 目录长这样：

| 文件 | 作用 |
| --- | --- |
| `custom-style.js` | 站点级 CSS，管排版、布局、导航栏、页脚 |
| `sidebar-toggle.js` | 左右侧栏开关，以及收起右栏时的卡片迁移 |
| `post-sidebar.js` | 文章页左栏的「本文分类」「本文标签」 |
| `profile-social.js` | 个人栏悬停气泡，QQ 图标点击复制 |
| `auto-excerpt.js` | 自动插入摘要标记 |
| `heading-number.js` | 标题自动编号 |
| `giscus-theme-sync.js` | 评论区跟随明暗切换 |
| `katex-inline.js` | 行内公式 `$...$` |
| `search-data.js` | 生成 `search.json` |
| `lib/markdown-scan.js` | 上面两个 markdown 脚本共用的扫描工具 |

## 正文读起来先要舒服

主题给正文 15.4px、行高 1.85。字号偏小，行距却松，中文段落就读得散。我把它定在 16px，行高保留 1.85，字体栈优先系统中文，不额外下载字体文件。

标题按层级给了 1.55rem、1.3rem、1.2rem，字重统一 600。段落间距 14px，标题上 26px、下 10px，代码块上下 14px。这套数字是试出来的，起初段落给到 20px，长文里段与段之间会显得空。

有一处不太好找。主题给 `figure.highlight` 写了 `margin: 1em 0 !important`，而代码块字号是 13px，这个 1em 实际只有 13px。我最初只写了 `margin: 16px 0`，完全没有生效，因为对面带 `!important`。

## 布局改成随宽度连续变化

最开始按断点写：1216px 以上一套数值，以下另一套，再加两档按宽高比微调。窗口拖过 1216px 时，卡片内边距会跳一下，侧栏宽度也跟着跳，很难看。

后来换成四个 `clamp()`，全部是视口宽度的线性函数：

```css
:root {
    --site-gutter: clamp(0.5rem, 14vw - 5rem, 10vw);
    --site-side:   clamp(240px, 18vw, 340px);
    --site-pad-y:  clamp(0.9375rem, 2.2vw + 0.45rem, 2.75rem);
    --site-pad-x:  clamp(0.6875rem, 3vw, 3rem);
}
```

留白在 320px 时 7px，768px 时 37px，1440px 时 132px，1920px 时 192px，也就是 10%，再宽也停在 10%。全站只剩一个断点，就是单栏和多栏之间的切换。

改的过程中有两个地方值得记下来。

Bulma 的 `.container` 是 `width: auto` 配 `flex-grow: 1`。我一开始改 `width`，页面纹丝不动。它抢的是剩余空间，只能靠 `max-width: calc(100% - 2 * var(--site-gutter))` 来限制。

另一个是我自己造成的。当时想给正文宽度封顶，写了 `max(calc(80vh * 16 / 9), 1024px)`。宽度固定在 2500px 不动，只把高度从 1500 拖到 500，`80vh` 就剩 400px，正文被压到 1024px，边距从 10% 涨到 29.5%。这个上限依附于视口高度，而高度跟正文宽度没有关系。去掉之后，宽度只跟宽度有关。

## 导航栏只保留一行

主题在 1025 到 1099px 会把导航栏摊成两行，logo 居中占一行，菜单另起一行。往下再窄回 1024 又变回一行。拖动窗口时就在这两种形态之间来回横跳。我统一成一套 flex 规则，左边放 logo 和菜单文字，右边放图标。

这里有个坑花了不少时间。主题的 `navbar.js` 判断要不要把菜单收进汉堡按钮，依据是 `scrollWidth > clientWidth + 1`。中文的最小内容宽度只有一个字，如果允许 flex 收缩，文字会先互相压住，容器却检测不到溢出，折叠点被拖到 400px 才触发，那之前一直是文字叠在图标上。

我先试过给菜单区加 `min-width: 0`，情况反而更糟。正确的做法是给菜单项锁死 `flex: 0 0 auto` 和 `white-space: nowrap`，让它们不肯被压窄。改完折叠点落在 510px 附近，正好是文字要撞上图标的位置。

折叠之后菜单区里只剩汉堡和图标，加一条 `margin-left: auto` 把它们整组推到最右，位置和展开时对齐，不会在折叠的一瞬间左右挪动。

导航栏还需要 `position: sticky` 和 `z-index: 100`。主题默认 `relative`，往下滚就滚走了。侧栏的吸附条 `is-sticky` 是 99，导航栏得比它高一层。另外给标题补 `scroll-margin-top: 4.6rem !important`，否则从目录跳转过去，标题会被导航栏压住一半。这条必须带 `!important`，主题样式表从 CDN 加载，跨域读不到 `cssRules`，排查时遍历 `styleSheets` 会以为没被覆盖。

## 侧栏收起后内容不能丢

左栏是个人资料、本文分类、本文标签、本文目录。右栏是分类、最新文章、归档、标签、贡献日历。两侧都能收起，状态存在 localStorage，刷新后保持。

直接让右栏消失，那些卡片就找不到了。我的做法是在收起时把右栏的 widget 逐个搬进左栏末尾，给每个节点打上 `data-sb-moved` 和序号，展开时按序号搬回去，中间插一条可以点击的「更多」做隔断。

两个坑。

主题会给右栏放一份影子副本 `.column-right-shadow`，用来让左右栏等高。卡片搬走之后副本还在，贡献日历会出现两份，卡片还会互相压住。搬移期间我给左栏加一个 `sb-migrated` 类，用 CSS 把副本藏掉。

另一个坑更隐蔽。我原本直接给 `.column-left` 加 `display: none` 来表示收起。目录卡片就住在左栏里，手机上的主题把它做成固定定位的浮层，由导航栏的目录按钮通过 `#toc.is-active` 控制。祖先进了 `display: none`，浮层永远出不来，症状是点了目录没反应，页面却被遮罩盖住。

后来改成只藏卡片本身：宽于 768px 时整列隐藏，窄于 768px 时只隐藏目录以外的子元素，把目录那一层留着。

## 手机上的侧栏入口

窄屏下贴边按钮会压住正文。它管的那摞卡片又排在正文下方，位置和作用对不上，用起来别扭。768px 以下我换成底部一颗悬浮胶囊，文案是「展开介绍卡片」和「收起介绍卡片」，半透明加背景模糊，浮在页脚之上，不占额外版面。

Pjax 切页之后要重新同步按钮和状态。否则从首页点进文章，胶囊还在，点它却没有反应。

## 内容层做点自动化

标题编号我改在 markdown 源头，没有动渲染后的 HTML。原因是主题的目录读的就是渲染后的标题文本，改在源头，正文和目录拿到同一串字符，序号天然一致。二级标题带点，写成 `1. `，更深层级写成 `3.1 `。手写过的旧序号先用正则去掉，免得出现「1. 1. 标题」。代码块里的 `#` 要跳过。

摘要希望首页只露出开头。在第一个二级标题之前插 `<!-- more -->` 就行。这里栽过一次：我那篇文章的正文里用行内代码提到过 `<!-- more -->` 这几个字，宽松的正则一看到就以为作者手动设过摘要，于是跳过这篇文章，首页把全文铺了出来。现在只认独占一行的标记，扫描时也跳过代码块。

搜索只索引标题和关键字。关键字由 `search-data.js` 读出来，生成 `search.json`，缺关键字的文章会在构建时打一条警告，提醒我只能按标题搜到。

这块出了两个 bug，症状都挺怪。先是搜索页上，我那篇讲改造过程的文章挂了一串莫名其妙的关键字，比如 `xxx`、`search-data.js`、`缺关键字的文章会在构建时打一条警告`。原因是提取用的是 `关键字\s*[：:]\s*([^\n]+)` 这个正则，全文全局匹配，还不锚定行首。文章正文里有一句说明写着「关键字写在正文任意一行，格式是 `> 关键字： xxx`」，于是从行内那个冒号开始，整行剩下的内容都被当成了关键字。

紧接着发现另一篇文章多出 STM32、FreeRTOS、内存管理。那篇正文里有一个小节专门演示关键字的写法，示例行就是 `> 关键字： STM32 FreeRTOS 内存管理`。示例本来就是给人看的，全被收进了索引。

改法是给关键字加上位置约束。只认行首的那一行，允许前面有引用符号 `>`，并且只扫第一个标题之前的开头部分，代码块一律跳过。这样正文里的说明和示例都不再被误认。

这两次其实是同一个毛病，正则只检查了文本里有没有这几个字，没检查它在文档的什么位置。文档里写到某个格式，和文档真的使用这个格式，在纯文本层面看不出区别。

## 零散但影响观感的地方

分享按钮在配置里整段删掉了，写 `null` 会触发 schema 警告。评论区换成 giscus，切换明暗之后要用 `postMessage` 通知 iframe 换主题，不然暗色页面里会留一块白框。主题的 KaTeX 只渲染 `$$`，我补了一段脚本把 `$...$` 也渲染掉。个人栏的图标去掉了浏览器原生 `title`，换成自定义气泡，QQ 图标点击复制号码。

页脚原来在 769px 以下直接堆成上下两块。现在跟导航栏用同一套逻辑，一行摆不下才换行，窄屏整体居中。

访客计数我关掉了。buSuanZi 返回的数字是五千多万，而且每刷新一次涨两三个，显然不是这个站的统计。

## 环境上踩到的

改完 `scripts` 里的文件，必须 `hexo clean` 再重启 server。`db.json` 里缓存着渲染结果，不清理会误以为改动没生效，我在这上面浪费过时间。

启动要让进程的工作目录等于项目目录，写成 `env -C <项目路径> ./node_modules/.bin/hexo server --draft --port 4000`。Babel 解析 `babel-plugin-inferno` 时按进程的工作目录找，目录不对会满屏报错。`npx hexo server` 也不合适，参数会被 npx 吃掉。

还有一处语法问题。`scripts` 里的 CSS 写在 JS 模板字符串中，注释里不能出现反引号，否则会把模板字符串提前闭合，报 `SyntaxError: Unexpected identifier`。

覆盖主题样式之前，先看它原本的选择器特异性。比如 `article.article .article-meta` 是 0,2,1，会压过 `.article-meta.level` 的 0,2,0，得写成 `body .article-meta.level` 才生效。带 Bulma `is-size-7` 的元素要改字号，只能加 `!important`。

## 文章页：标题态与阅读态

第一版文章页，左栏把「简介 + 本文分类 + 本文标签 + 本文目录」从上到下堆着。
光简介卡片就占了大半屏，整列比视口还高。而左栏是吸附（`position: sticky`）的
，比视口高的吸附元素，底部永远露不出来——正文读到哪里，目录都还停在屏幕外。

于是分两个状态：

- 标题态（正文还没开始滚）：左栏只留 简介 + 本文分类 + 本文标签，目录整张藏起来
- 阅读态（正文开始滚）：左栏换成 目录 + 底部按钮排 + 本文分类 + 本文标签

状态靠 `body.is-reading` 驱动。桌面档判断的是正文那一列的 `scrollTop`，手机档没有
那套布局，仍然看页面滚动，并各用一个阈值进出（进 48px、退 8px），免得在临界点上
来回抖。

顺带删掉了目录卡片里的 `transition`。主题给目录的 `<ul>` 加类名时会带着布局一起
动画，点一个三级标题像卡了一下。

## 正文列自己滚，顶部那条进度条才有意义

左右两栏都有固定的高度与内边距，正文却跟着整页滚，滚动条贴着视口最右边、贯穿上下
，跟两侧卡片的留白完全对不上。所以把滚动容器放到 `.column-main` 上：它自己吸附、
自己有高度、滚动条只占卡片那一段，评论卡片也在这条滚动区域里，滚到底就能看见。

这里踩了一个很典型的坑。顶部留白原本写在 `padding-top` 上，而**滚动容器的内边距属
于「可滚动内容」**，一滚动就被带走，正文卡片顶边会顶到 91，比左右两栏的卡片（101
）高出一块。改成 `padding-top: 0` + `border-top: .75rem solid transparent` 才稳定
：边框在滚动区域之外，滚多少都不会被吃掉。

顶部那条蓝色进度条也重做了。主题自带的是 Pace，只认页面加载。文章页真正的滚动发生
在 `.column-main` 里，Pace 量不到；更糟的是评论组件加载慢，它会一直卡在 81% 不动
。我把 `plugins.progressbar` 关掉，自己画一条 3px 的进度条，按正文滚了多少来算，
手机上退化成整页进度。

## 三栏得真的等高

三栏统一用 `calc(100vh - 10.25rem)`：上留白 42 + 顶栏 59 + 下留白 42。页面本身
正好一屏，不再多出一截空间——不然窗口一矮，在标题态两侧还能跟着页面“滚”，而那
时候其实什么都不该动。

左右两栏去掉底部 padding，再让**最后一张可见卡片吃掉剩余高度**，底边才能和正文卡
片贴到同一条线。不做这一步，左栏内容只到 828、正文到 958，看着像错位。

按钮排的位置也改过两轮。它一开始挂在目录卡片底部（卡片内），后来为了绕开主题给卡
片绑的 `toggleToc` 挪到卡片外面，结果目录卡片永远比正文矮一截（实测矮 38px）。最
后还是放回卡片内部当底部条，同时在按钮的点击上加 `stopPropagation`——卡片上那个
`toggleToc` 是手机浮层的开关，不拦的话点完目录会变成浮层。

## 放不下就少放几张

窗口很矮的时候（笔记本分屏、手机横屏），侧栏塞不下所有卡片。这里的顺序是：

1. 右栏「最新文章」能放几条放几条，一条都放不下就整张收起
2. 还不够就收贡献日历
3. 还不够就把两侧的卡片从后往前收，至少留第一张

这样任何一种高度下都是「少显示几张」，而不是让整页或整栏滚起来。判断的基准是最后
一张可见卡片的底边，栏底再留 8px。

有一类坑比较隐蔽：卡片高度会被**晚一步**的东西撑高——图标字体、中文字体、贡献日
历的图片和它自己的脚本。初始化时量着“放得下”，两秒后就溢出了。所以布局在
200 / 600 / 1200 / 2000ms 各再对一次，每次只有几毫秒。

## 侧栏的抽动

从标题态进阅读态时，右栏会瞬间变样：内容变多、位置错开。原因是我把裁剪逻辑写成了
「阅读态跳过」，而标题态为了塞进一屏只留一条最新文章，两边对不上。

改法是让「最新文章」永远排在右栏最下面。它自身的长度变化只会往下长，上面的分类、
归档、标签、日历顶边一个像素都不动——等于自然继承了标题态的位置。再在进阅读态的瞬
间把右栏 `scrollTop` 归零，避免它停在上一次滚动到的地方。

## 底栏

主题的 `footer` 没有开关，`footer.jsx` 里是无条件渲染。要「无底栏」只能在自定义
样式里 `display: none`，顺带拿掉底部那 42px 占位。

## 这一轮的重构

功能堆完之后把 `reading-toc.js` 整个理了一遍：

- 元素查一次缓存起来（`el.main` / `el.left` / `el.right` / `el.toc`），滚动回调
  里不再查 DOM
- `localStorage` 的读写统一收进 `stored()` / `store()`，隐私模式抛异常也不会炸
- 两个开关共用一套 `syncButton(kind)`，按钮由 `makeButton()` 生成
- 侧栏布局收口到一个 `layoutColumns()`，顺序固定为：复位 → 右栏裁剪 → 整列裁剪
  → 最后一张卡片拉伸。顺序反过来就会出问题，被拉长的卡片永远“放得下”，裁剪直接
  失效

改完之后每次需求都只是改几十行，剩下的时间都在量像素：顶边 91 还是 101、底边 947
还是 958、卡片矮了 38px 还是 10px。

## 收尾

整轮下来最耗时间的部分在设计之外，全是弄清楚主题的行为：`scrollWidth` 和 `clientWidth` 的溢出判定、影子副本、目录浮层的开关方式，以及各种特异性互相压制。这些搞明白之后，改动就变成几十行 CSS 加一个小脚本。

我的理解是，改主题的难点在于读代码，写样式反而快。
